## Host discovery

From your attacker box on the same lab network:

```
sudo netdiscover -r 192.168.56.0/24
# or
sudo nmap -sn 192.168.56.0/24
```

Compare the results against hosts you already know (your attacker box, the
gateway). The unfamiliar address is your target. Export it for convenience:

```
export IP=192.168.56.X
```

## Enumeration

Scan all ports, then fingerprint the open ones:

```
nmap -p- --min-rate 2000 -oN allports.txt $IP
nmap -sVC -p <open,ports> -oN services.txt $IP
```

Read every line. The interesting service is a web server, so identify what is
running on it:

```
whatweb http://$IP
gobuster dir -u http://$IP -w /usr/share/wordlists/dirb/common.txt
```

The front page is a content management system. Pin down which CMS it is and its
major version. That version string is your lead, so write it down exactly.

## Foothold (user)

The CMS out front is old enough to have a public exploit against that major
version.

1. Take the CMS name and version from your scan and search public exploit
   sources for a matching advisory.
2. Read the exploit so you understand what it does, then set your target address
   and any required options.
3. Run it to get command execution and land a shell as the web account.
4. Enumerate from inside the shell. The CMS config file holds database
   credentials, and the database itself is worth a look. Then read the user flag:

```
cat user.txt
```

Proof token: `MOB{outdated_cms_lets_you_in}`.

## Privilege escalation (root)

With a shell, run the standard checks:

```
id; uname -a
sudo -l
find / -perm -4000 -type f 2>/dev/null
```

Read the SUID list carefully. One binary on this box carries the SUID bit when
it has no business doing so. Match it to a known escalation technique, use it to
spawn a root shell, and grab the final flag:

```
cat /root/root.txt
```

Proof token: `MOB{suid_binary_owns_root}`.

## Lessons learned

- The outdated CMS was the whole front door. Unpatched web software is the most
  common way onto a box, and the version number told you which exploit to reach
  for.
- Credentials in a config file are a foothold multiplier. Always read the app
  config and the database once you are inside.
- Privesc is a checklist you run every time, not a lucky guess. A SUID bit on the
  wrong binary is one of the first things that checklist should catch.
